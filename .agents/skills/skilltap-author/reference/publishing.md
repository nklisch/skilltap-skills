# Publishing Reference

Three channels for distributing a skill or plugin. Choose based on audience, trust requirements, and discovery needs.

## Channel 1: Git host (any)

The simplest option. Push your skill directory to any git host. Users install by URL.

```bash
git init && git add . && git commit -m "Initial commit"
git remote add origin https://github.com/you/my-skill
git push -u origin main
git tag v1.0.0 && git push --tags
```

Users install with:
```bash
skilltap install github:you/my-skill           # latest default branch
skilltap install github:you/my-skill@v1.0.0    # pinned tag
skilltap install https://github.com/you/my-skill
```

**Trust tier:** `unverified` by default. Upgrades to `curated` if a tap maintainer adds the entry with `trust.verified: true`.

**GitHub Artifact Attestations** (optional enhancement): Add a workflow step using `actions/attest-build-provenance@v2` to cryptographically link your release artifacts to the workflow run. This is advisory metadata — skilltap reads it but the trust tier for bare git installs stays `unverified` unless tap-curated.

## Channel 2: npm

Publish to the npm registry for versioned distribution and provenance.

### Setup

Use `skilltap create --template npm` to scaffold. The template generates:
- `SKILL.md`
- `package.json` with `files: ["SKILL.md", "skills/**"]`
- `.github/workflows/publish.yml` pre-configured for provenance

### `package.json` minimum viable fields

```json
{
  "name": "@yourscope/my-skill",
  "version": "1.0.0",
  "description": "...",
  "keywords": ["agent-skill"],
  "license": "MIT",
  "files": ["SKILL.md", "skills/**"],
  "repository": { "type": "git", "url": "https://github.com/you/my-skill" }
}
```

### Publishing with provenance

```bash
npm publish --access public --provenance
```

The `--provenance` flag generates a Sigstore-signed SLSA Build Level 2 attestation when run from a public GitHub Actions workflow with `id-token: write` permission. This cryptographically links the package to the source repo and workflow run that produced it.

Without `--provenance`, the package still publishes but gets the `publisher` tier (identity known, provenance unverified).

### GitHub Actions workflow (generated by `--template npm`)

```yaml
name: Publish
on:
  release:
    types: [published]
permissions:
  id-token: write      # required for --provenance
  contents: read
  attestations: write  # required for attest-build-provenance
jobs:
  publish:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          registry-url: https://registry.npmjs.org
      - run: npm publish --provenance --access public
        env:
          NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}
      - uses: actions/attest-build-provenance@v2
        with:
          subject-path: SKILL.md
```

Trigger: create a GitHub Release. npm will reflect the new version within minutes.

Users install with:
```bash
skilltap install npm:@yourscope/my-skill
skilltap install npm:@yourscope/my-skill@1.2.0    # pinned
```

## Channel 3: Tap

Submit to an existing tap or run your own.

### Submit to an existing tap

Open a PR against the tap maintainer's `tap.json`, adding your entry:
```json
{
  "name": "my-skill",
  "description": "One-line description",
  "repo": "you/my-skill",
  "tags": ["category"]
}
```

The maintainer reviews, sets `trust.verified: true`, and merges.

### Run your own tap

```bash
skilltap tap init my-tap
cd my-tap
# Edit tap.json — add your skills and plugins
git remote add origin https://github.com/you/my-tap
git push -u origin main
```

Users add your tap once:
```bash
skilltap tap add my-tap https://github.com/you/my-tap
```

Then install from it by name:
```bash
skilltap install my-skill    # resolves via tap
```

See [tap-format.md](tap-format.md) for the full `tap.json` schema.

## Trust tiers by channel

| Publishing path | Trust tier |
|-----------------|-----------|
| npm + `--provenance` (from public GHA + `id-token: write`) | `provenance` |
| npm without provenance | `publisher` |
| Bare git, tap-curated (`trust.verified: true`) | `curated` |
| Bare git, no tap | `unverified` |

Trust tiers affect what warnings (if any) users see on install. See [../skilltap-find/](../skilltap-find/) for how users browse by trust tier.

## Versioning

Tag releases semantically. Users can pin to a tag with `@vX.Y.Z`.

```bash
git tag v1.2.0
git push --tags
```

Breaking changes → bump major. New fields/features → bump minor. Fixes → bump patch.

For npm, version lives in `package.json`. Update it before publishing:
```bash
npm version patch    # or minor / major
npm publish --provenance --access public
```

## Pre-publish checklist

1. `skilltap verify` exits 0.
2. `frontmatter.name` matches the directory name exactly.
3. Description is action-oriented and exhaustive — confirm the agent loads the skill on plain-language prompts.
4. Static scan clean (no anti-trojan-source or dangerous-pattern warnings).
5. Total skill size < 50 KB.
6. `README.md` for humans browsing the repo.
7. Release tag (`git tag v1.0.0 && git push --tags`).
